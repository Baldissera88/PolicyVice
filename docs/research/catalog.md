# Policy CSP catalog

PolicyVice carries an offline catalog of every Policy CSP setting in Microsoft's documentation. It gives MDM settings a real name instead of a split policy name, explains values (`1 (Allowed)`), and maps each setting to its Group Policy registry value so conflicts can be found outside the ADMX-backed areas.

| Item | Value |
|---|---|
| Data file | `res/PolicyCsp.tsv.gz`, embedded as the manifest resource `PolicyCsp.tsv.gz` |
| Generator | `tools/build_csp_catalog.py` (Python 3, standard library only) |
| Reader | `src/CspCatalog.cs` |
| Tests | `tests/CatalogTests.cs` |
| Source | `https://github.com/dodexahedron/windows-itpro-docs`, branch `public`, commit `30fa38219c454ecdcd34bae7aa84a93783132286` (9 July 2025) |
| License of the data | CC BY 4.0, Microsoft Corporation and contributors, see [NOTICE](../../NOTICE) |

## Source

The Policy CSP reference on Microsoft Learn (`learn.microsoft.com/windows/client-management/mdm/policy-csp-<area>`) is built from `windows/client-management/mdm/policy-csp-<area>.md`. The pages name two repositories:

- `MicrosoftDocs/windows-docs-pr`, branch `live`: the private repository the pages are published from.
- `MicrosoftDocs/windows-itpro-docs`, branch `public`: the public mirror used for feedback and contributions.

In November 2026 neither can be cloned. Git over HTTPS answers `Repository not found` for both, while other MicrosoftDocs repositories such as `windowsserverdocs` and `azure-docs` still clone. This matches Microsoft's announcement on the Tech Community *Skills Hub* blog, "Changes to Microsoft Learn's public documentation repositories" (September 2026): most Learn documentation repositories are retired by the end of December 2026, they stop being publicly visible, and only personal forks remain.

So the catalog is built from a public fork. About 60 forks of `windows-itpro-docs` were checked. The most recent one is `dodexahedron/windows-itpro-docs`. Its `public` branch head is Microsoft's own publish merge, `Merge pull request #10984 from MicrosoftDocs/main`, with the message `[AutoPublish] main to live - 07/09 10:34 PDT`, dated 9 July 2025. It is an unmodified copy of the official `public` branch as of that day. The next most recent forks are from February 2025 (`ugurkocde`) and June 2023 (`TerryWarwick`). The fork carries Microsoft's `LICENSE` (CC BY 4.0), `LICENSE-CODE` (MIT) and `ThirdPartyNotices` files.

Content was checked against the live Learn pages (updated 23 October 2026):

| Check | Result |
|---|---|
| `Update/AllowAutoUpdate`: OMA-URI, description, values 0 to 5 with 2 as the default, and the GP mapping `AutoUpdateCfg`, Configure Automatic Updates, `Software\Policies\Microsoft\Windows\WindowsUpdate\AU`, `WindowsUpdate.admx` | Same |
| `WindowsAI/DisableAIDataAnalysis`: friendly name, location, path, registry key and value, `WindowsCopilot.admx` | Same |
| Settings in the `WindowsAI` area | 14 in the catalog, 21 on Learn |
| Settings in the `Update` area | 75 in the catalog, about 97 in the Learn table of contents |

Settings that already existed in July 2025 match. Settings Microsoft added after July 2025 are missing.

If an official public copy comes back, or a fresher fork turns up, rebuild from it with the command below. The source and commit are written into the catalog header, so nothing else changes.

## Regenerate

```sh
git clone --depth 1 --branch public --filter=blob:none --sparse https://github.com/dodexahedron/windows-itpro-docs /tmp/winitpro
git -C /tmp/winitpro sparse-checkout set windows/client-management/mdm
python3 tools/build_csp_catalog.py /tmp/winitpro
./tests/run.sh
```

The generator reads the commit, date, branch and origin from the checkout and writes `res/PolicyCsp.tsv.gz`. Options:

| Option | Use |
|---|---|
| `-o <file>` | Write somewhere else |
| `--tsv <file>` | Also write the uncompressed TSV, for review or diffing |
| `--source <url>`, `--commit <sha>`, `--date <yyyy-mm-dd>` | Give the source when the input is not a git checkout |

To pin the exact commit used here, run `git -C /tmp/winitpro fetch --depth 1 origin 30fa38219c454ecdcd34bae7aa84a93783132286` and then `git -C /tmp/winitpro checkout FETCH_HEAD` before running the generator. The output is reproducible: rows are sorted, and the gzip header has no time stamp or file name. Two runs on the same commit give the same bytes.

## How it is parsed

The current pages are generated by Microsoft's tooling. Each setting is a block with fixed HTML comment markers:

| Section | Gives |
|---|---|
| `<!-- X-OmaUri-Begin -->` | Area and name from `./Device/...` and `./User/.../Policy/Config/<Area>/<Name>`. The scope is Device, User or Both from which URIs are listed. If there is no URI, the scope comes from the Applicability table. |
| `X-Description` | The first two sentences as plain text, with links, bold, code, includes, notes and HTML removed, at most 400 characters. A leading copy of the title and one-word sentences such as `Important.` are dropped. If the section is empty, the Editable section is used. |
| `X-DFProperties` | Format (`int`, `chr`, `bool`, `b64`), default value, and the range from `Range: [a-b]` |
| `X-AllowedValues` | The value table, `Value` or `Flag`, with `(Default)` taken off the key. A meaning is kept whole up to 100 characters, otherwise its first sentence is kept, at most 160 characters. XML schemas in this section are skipped. |
| `X-GpMapping` (**Group policy mapping**) | Name, Friendly Name, Element Name, Location, Path, Registry Key Name, Registry Value Name, ADMX File Name |
| `X-AdmxBacked` (**ADMX mapping**) | The same fields for ADMX-backed settings, which also get `AdmxBacked = 1` |

The friendly name is the Group Policy friendly name. For Security Settings, such as security options, user rights and audit, it is the Group Policy name (`Accounts: Block Microsoft accounts`). Otherwise it is a title made from the policy name (`ConfigureSystemCryptographyForceStrongKeyProtection` becomes `Configure System Cryptography Force Strong Key Protection`), with words like BitLocker and OneDrive kept together.

Table rows are split on `|` outside code spans, because some cells contain `` `|` ``. One page, `policy-csp-feeds.md`, still uses the older hand-written format (`<!--Policy-->` blocks with an `ADMX Info:` list). It has its own parser. The `policy-csp-*.md` files that are not policy pages, and areas with two pages, are reported and not added twice.

## File format

UTF-8 TSV, gzip-compressed. It starts with `#key<TAB>value` header lines (`format`, `upstream`, `source`, `branch`, `commit`, `date`, `license`, `entries`), followed by one header row and one row per setting, sorted by area and name. In a cell, `\` becomes `\\`, a tab becomes `\t`, a newline becomes `\n` and a carriage return becomes `\r`.

| Column | Contents |
|---|---|
| Area, Name | As in the OMA-URI, such as `Update`, `AllowAutoUpdate` or `ADMX_Bits`, `BITS_DisableBranchCache` |
| Scope | `Device`, `User` or `Both` |
| FriendlyName, Description | Plain text |
| Format, Default, Range | From the description framework properties |
| Values | `value<TAB>meaning` pairs separated by newlines, in the order of the documentation |
| AdmxBacked | `1` for ADMX-backed settings |
| AdmxFile, AdmxPolicy | Such as `WindowsUpdate.admx`, `AutoUpdateCfg` |
| GpPath, GpLocation, GpElement | Group Policy path, Computer or User Configuration, element name |
| GpKey, GpValueName | Registry key without the hive (`Software\Policies\...`) and value name |

`CspCatalog` finds columns by their header name, so columns can be added later without breaking older readers.

What a partly parsed setting lacks:

| Missing | Count | Why |
|---|---|---|
| Registry key | 71 | The documentation has no registry key. These are 43 ADMX-backed settings marked `ADMX-Not-Found` (ADMX_MSS-legacy, MSSecurityGuide, MSSLegacy, ADMX_AdmPwd and others), 27 newer settings whose mapping only shows an internal path such as `WindowsAI > AT > WindowsComponents > WindowsAI` (WindowsAI, Start, NewsAndInterests, the legacy Update deferrals), and Feeds/FeedsEnabled, whose old-format page gives the ADMX file but no key. |

| Description | 23 | The documentation says `Description-Source-Not-Found` and has nothing in the Editable section either |
| Allowed values | 4 | The values are an XML schema, not a table (LocalUsersAndGroups/Configure, RestrictedGroups/ConfigureGroupMembership, MixedReality/ConfigureSharedAccount, ApplicationManagement/ScheduleForceRestartForUpdateFailures) |

Security Settings mappings (Audit, UserRights, LocalPoliciesSecurityOptions, SystemServices, the DeviceLock password policies) have no registry key by design. They are not counted as partial.

## Known gaps

- **Freshness.** The data is the documentation as of 9 July 2025. Settings added later, such as newer WindowsAI and Update settings, are not in the catalog and fall back to the split policy name.
- **Value names.** 990 settings have a registry key but no value name, because the documentation names the ADMX policy and element but not the value. Examples are `Update/AllowAutoUpdate` (the value is `AUOptions`) and `DeliveryOptimization/DODownloadMode` (`DODownloadMode`). `FindByRegistry(key, null)` returns every setting under a key, and `FindByAdmx(file, policy)` together with `AdmxCatalog.ForValue` covers the rest when the ADMX files are on the device.
- **Value meanings.** Group Policy and MDM values do not always mean the same thing. For example, `Defender/AllowRealtimeMonitoring = 0` is the same as `DisableRealtimeMonitoring = 1`. The catalog documents MDM values only.
- **Many-to-one mappings.** Several CSP settings can map to the same Group Policy (the `Update/Defer*` settings, and IE zone templates that share a key). `FindByRegistry` returns all of them.
- **Scope.** The scope is taken from the documented OMA-URIs. A few settings work in both scopes but are only documented for one.
- **Descriptions** are shortened to two sentences. Long value meanings are shortened to their first sentence.
- **Not in the catalog:** CSPs outside the Policy CSP, such as BitLocker CSP, Firewall CSP, Defender CSP `Configuration/*` nodes and LAPS. Their nodes are not under `Policy/Config`.
